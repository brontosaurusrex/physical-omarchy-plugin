## Controls

The on-screen help incorrectly described Esc as pause/replay exit. Esc now
consistently closes the window and releases the pointer. Replay could be left
only by an engine Escape event, which the native window intercepted; Shift+K
and the menu's Exit replay button now leave replay while preserving the live
session. The sound toggle works on Ready and in menus. The debris button now
shows the saved master switch controlled by R rather than the per-level lab
setting. The toolbar and menu play buttons now control replay playback as well
as live play; live-only menu actions are disabled during replay. The help and README list the diagnostics alias I, Shift+F and U. The help also
clarifies that Q closes outside the physics lab; Esc closes in every state.

`tests/keyboard.py` sends real Qt key events into the QML window, using private
progress and export directories. Its 51 checks cover Ready controls, Enter,
A/D and arrow movement, Space pause/resume, sound, magnets, zapper, extra ball,
manual rescue, automatic paddle, diagnostics, FPS, replay direction/scrubbing,
SVG/trail exports, both replay exits, lab entry/exit, temporary unlock and level
navigation, help, menu Escape, reopen/start, Space+F in both directions and Q.
The rescue assertion checks its explicit status message. The pointer test
separately covers right-click lock/release/reacquisition, menu release, Escape
in normal/fullscreen/menu states and reopening on the real Wayland compositor.
Qt input is synthesized by QtTest; this is not a physical keyboard/mouse test.

## Audio

The previous port did not use sounds exactly as the web game does. It used
uncompressed source masters rather than the compressed runtime bank, fixed
wall/paddle recordings and approximate tone samples. Several generated cues
lost waveform, frequency sweep, timing, gain and pan. Generic magic hits used
recordings instead of the original two generated tones.

| Sound | Original behavior retained by the updated port |
| --- | --- |
| Normal brick | Random choice from the 21 runtime samples, without immediate repeat; speed-dependent gain/filter, randomized playback rate and Q, hit-position pan. |
| Generic magic brick | Generated sine 660→990 and triangle 990→1480 Hz cues with original variation, duration, delay and pitch scaling. |
| Activated power-up | Its own runtime sample for each of the 12 feature types; original randomized rate/gain/filter/Q and pan. |
| Wall / paddle | Original randomized triangle tone; paddle also adds its low sine body. |
| Ball-ball / unbreakable | Original speed-dependent metallic tick / low impact tone pair, with position and original parameters. |
| Zapper, life loss, game over, last brick, completion and win | Original Go tone/chord scheduling retained; waveform, start/end frequencies, duration, gain and delay reach the native mixer. |
| Repeated feature | Old voice fades over 18 ms; replacement starts after 9.9 ms rather than layering another long cue. |
| Dense bursts | Shared maximum of three normal/generic magic hit starts per engine frame; eight active normal sample voices and four active feature cues. Full feature capacity falls back to the original generated power-up pattern. |

The web config caps feature filtering at **500 Hz** despite its 800 Hz clamp
floor. The original clamp order returns the 500 Hz cap for the configured
ranges, and the port preserves that behavior. It is not silently corrected.
Brick/magic/synth bus gains are 0.20/0.20/0.80; the native master volume starts
at 25% and persists. Generic magic sounds and zapper brick pitch remain distinct
from the feature activation sample. Muting/closing stops the native voices;
level changes stop feature cues. One persistent QAudioSink avoids rapid backend
stream creation/restarts.

`sounds/samples.json` records source and output hashes for all 33 runtime
samples, decoded to 48 kHz stereo PCM16. `tests/audio_assets.py` checks the bank,
format and hashes. Passing `/home/b/source/physical/dev` also verifies the
original source hashes. Native PCM tests check output timing, gain, pan, filters, voice caps, retrigger
and cleanup. Go tests check wall/paddle collision events, all 12
feature identities, full oscillator parameters, magic/zapper pitch, burst
budget and the feature filter cap; the QML test checks random bank selection,
loaded assets and native playback.

The room graph now follows the original per-level presets: dry/wet gains, input
and output filters, three reflection taps, and damped feedback around tap 3.
The Go adapter sends settings only when they change; QML forwards them before
playing that packet's sounds. Gains and delay times ramp over 160 ms. Filter
coefficients update every 32 samples during transitions, then stay cached.
Low/high-pass resonance now uses [Web Audio's dB convention](https://www.w3.org/TR/webaudio/#filters-characteristics), while band-pass Q
is linear. Stops clear voices and echoes; silent tails are limited to 12 seconds.
Native tests cover filter response, reflection timing, all three taps, feedback,
stereo isolation, stable transitions, dry bypass and stale-tail cleanup. Engine
and QML checks verify that the actual level settings reach the mixer.

Audio is **not bit-identical** to the browser. Native oscillators, resampling,
transition filter updates and scheduling differ from Web Audio, and browser decoding
can differ from FFmpeg PCM conversion. Random selection uses the same rules,
not the same random sequence. The mixer has a total safety limit of 64 voices,
so pathological overlapping synth bursts may drop tones. Tests verify events,
parameters, assets and playback state; they do not replace a perceptual listening
comparison or prove identical speaker output.

The first level's Ready title was renamed from “SLAY” to “P H Y S I C A L” at
the user's request. The protocol test checks its rendered text; level layout and
the original checkout remain unchanged.

## Magnetic debris CPU optimization

An engine CPU profile of active multiball gameplay identified repeated hash-grid
lookups in `nearestMagneticBrickForDebris` as a major cost. Brick construction
now also fills a direct array of cells. Magnetic debris queries use that array;
cell contents, row/column traversal order, live/unbreakable checks and distance
comparisons remain the same. The original map path remains as a fallback.
Regression tests compare 3,000 queries over sparse/duplicate cells and successive
brick destruction, requiring exactly equal target coordinates and distances.

A controlled engine-only comparison used the same seed and 1,800 visual frames
per level, with fresh rounds every 900 frames. Both modes execute physics,
drawing-packet preparation and JSON encoding; there is no Qt window or audio
playback in this benchmark.

| Level | Original map path, ms/frame | Direct cell path, ms/frame | Reduction in engine CPU time |
| --- | ---: | ---: | ---: |
| 23 | 2.034 | 1.415 | 30.5% |
| 26 | 2.699 | 1.807 | 33.1% |
| 27 | 1.766 | 1.233 | 30.2% |

These are CPU timings, not displayed FPS. The result does not establish a fixed
30% FPS gain or isolate every renderer/driver bottleneck.

## Torture test and freeze detection

The benchmark can rotate levels and force fresh rounds, preventing a long run
from spending most of its time on a quiet final brick. It tracks painted frames,
engine replies and engine errors. A Python reader thread and monotonic watchdog
run outside Qt: eight seconds without a gameplay heartbeat fails the test,
including a blocked UI thread. Startup has a 25-second allowance; total runtime
also has a hard deadline. Engine replies that stop while Qt is alive fail at the
next sample. Failure cleanup terminates the isolated process group, including
a deliberately stopped engine; the installed shell/game is unaffected.

Negative tests deliberately sent SIGSTOP after the third gameplay sample:

- UI process: external heartbeat watchdog detected the freeze and failed.
- Engine process: the QML harness detected stalled engine replies and failed.

Both tests exited with status 1 as expected. Successful normal runs require the
final pass marker as well as exit status zero. The watchdog establishes process
liveness, not a guarantee against every possible gameplay logic bug.

The earlier ten-minute run, before room acoustics and the direct-grid
optimization, completed **600.71 seconds**, with **23 round resets** and
**50.6 overall painted FPS**. It reached 150 debris pieces and produced no
engine error, detected freeze, crash or Qt socket warning. The test used Intel
HD Graphics 520, Qt 6.11.2 / Quickshell 0.3.1, OpenGL, the normal 1080×542
logical-pixel window, sound at 25%, automatic paddle, magnets, zapper and extra
balls. No build or other test ran alongside this measurement.
